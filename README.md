# Pointmaxing

Kalkulator som viser hvor mange SAS EuroBonus-poeng et kjøp gir via Trumf Netthandel, Klarna og SAS Online Shopping, og hvilket program som lønner seg. Landvalg: Norge, Sverige og Danmark (Trumf bare i Norge; programmer, satser og butikker ligger per land i datafilene). Brukeren skriver inn kjøpesum og butikkens sats i hvert program, velger betalingskort og Klarna-abonnement, og får en rangert sammenligning.

## Kjøre

```bash
npm install
npm run dev
```

`npm test` kjører regnetestene, `npm run build` bygger til `dist/`.

`npm run hent` henter butikksatser på nytt fra Trumf Netthandel (paginert liste), SAS Online Shopping (JSON-API) og Klarna (katalog-API-et bak klarna.com/no/store/?type=CASHBACK) og skriver `src/data/stores.json`. `npm run build:enkeltfil` pakker bygget til én HTML-fil (`dist/pointmaxing.html`).

## Struktur

- `src/data/programs.json` og `src/data/cards.json` – alle satser, vilkår, kilder og «sist verifisert». Ingen satser i koden.
- `src/data/stores.json` (generert av `npm run hent`) og `src/data/partners.json` (håndholdte partnere, tom nå) – butikksatser og logoer, slått sammen i `src/data/index.ts`.
- `src/data/index.ts` – eneste stedet som leser datafilene. Bytt ut denne for API/database.
- `src/lib/calc.ts` – ren regnemodul (testet i `calc.test.ts`).
- `src/components/` – skjema og resultatvisning.
- `docs/research.md` – researchen satsene bygger på.

## Butikksider, historikk og språk

- `npm run build` lager i tillegg én statisk side per butikk (`dist/no/kicks/index.html` osv.), landsider, `404.html`, `sitemap.xml` og `robots.txt` via `scripts/bygg-butikksider.mjs`. Adressen `/se/kicks` åpner Kicks i Sverige direkte.
- `src/data/history.json` fylles av `npm run hent` med `[dato, sats]` hver gang en sats endrer seg; kalkulatoren viser en liten kurve og «høyeste sats siden …» per program når en butikk er valgt.
- Språk og tallformat følger flagget (norsk, svensk, dansk). Tekstene ligger i `src/i18n.ts`; svenske og danske programtekster ligger i `programs.json`.
- Poengverdi (øre per poeng) kan justeres i kalkulatoren og gir «≈ kr» ved siden av poengene.

## Sider, varsler og utvidelse

- Sider per land: `/no` (kalkulator), `/no/kicks` (butikk), `/no/butikker` og `/no/butikker/elektronikk` (katalog med kategori), `/no/nytt` (kampanjer og satsendringer siste 30 dager) og `/no/kort` (kort som gir EuroBonus). Alle lages statisk av `scripts/bygg-butikksider.mjs`.
- Kategorier og butikkdomener hentes av `npm run hent` (Trumf-kategorisider, SAS-kategorier, Klarnas `category` og `merchantUrl`). Kategorinavn ligger i `src/data/kategorier.json`.
- Butikklogoer (`npm run hent`): håndplukkede offisielle logoer (`src/data/partnerlogoer.json`, `public/logos/partnere`) → Trumf → Klarna → SAS (bare ekte logoer med gjennomsiktig bakgrunn – SAS-feedens logofelt er ofte hvite flater eller skjermbilder, og `image_url` er markedsbilder som ikke brukes) → samme butikk i et annet land → merkevarens ikon i Klarnas katalog (søk på navn, eksakt treff). Uten treff vises forbokstaven. Dommen over SAS-logoer (`sjekk:<url>`) og søkene (`sok:<land>/<id>`, bom prøves igjen etter 30 dager) huskes i `public/logos/manifest.json`.
- Besøkstall: sett `cloudflareToken` i `src/data/analyse.json` (Cloudflare Web Analytics, gratis, uten informasjonskapsler), så legger `main.tsx` inn beacon-scriptet i produksjon og personvernsiden nevner det. Tomt token = ingen måling.
- Kortvelgeren ytterst i sideraden (`Kortvelger.tsx`) bytter kort og Klarna-nivå fra alle sider; kortbildene lages av `npm run kortbilder` (`scripts/hent-kortbilder.mjs` → `public/kort/`, oppslag i `src/data/kortbilder.json`): Amex' egen kortkunst hentes, mens Klarna (Max rosegull, Premium sølv, Plus sort), SAS Mastercard World/Premium, Lunar og Revolut tegnes som SVG i samme format etter hvordan kortene ser ut. Kort uten bilde får et monogram.
- Layout: under 640 px ligger sidene i en nedtrekksmeny (`Sidevelger.tsx`) til venstre i samme rad som kortvelgeren, så menyen aldri brekker. «Legg til i Chrome» er en diskret knapp øverst ved flaggene (skjult på mobil), stjernen for å følge butikk står ved butikksøket, alt om tallene (merknader, forbehold, kilder, signatur) ligger bak «Om tallene» i bunnen, og under 560 px vises programmene som rader i billetten i stedet for kolonner.
- PWA: `public/manifest.webmanifest` og `public/sw.js` (registreres bare i produksjon) gjør at siden kan legges på hjemskjermen og virker uten nett når den først er åpnet; `share_target` lar deg dele en butikklenke eller tekst til appen fra andre apper (`?url=`/`?tekst=` finner butikken på domene eller navn).
- `/personvern` (nettside + utvidelse, med engelsk oppsummering) og `/utvidelse` (hva utvidelsen gjør og «Legg til i Chrome» – `chromeWebStoreUrl` i `src/data/utvidelse.json`, godkjent i Chrome Web Store 25.09.2026: https://chromewebstore.google.com/detail/pointmaxing/aenlapgeapjjmbbadigncengafnfkjhp; uten lenke vises zip-nedlasting med trinn). `npm run build` pakker `dist/pointmaxing-utvidelse.zip` og `-firefox.zip` (`scripts/pakk-utvidelse.mjs`). Oppføringstekst og tillatelsesbegrunnelser til Chrome Web Store ligger i `extension/BUTIKK.md`, skjermbilder i `docs/butikk/`.
- Nivåpoeng: SAS Online Shopping gir 20 nivåpoeng per 100 bonuspoeng til 30.12.2026 (`nivaapoeng` i programs.json, NO og DK verifisert), SAS Amex Elite 6 per 100 kr og SAS Mastercard Premium 25 % av kortpoengene (`nivaapoengPer100`/`nivaapoengAndel` i cards.json). Vises som «+ N nivåpoeng» under poengene.
- Kort-siden: kortbildet først i hver rad (samme bilder som kortvelgeren), og samme tre tall for alle kort og Klarna-medlemskap – poeng per 100 kr, pris per måned (`prisPerMnd`, basispris uten kampanjer; kort som prises per år er delt på tolv, `prisPerMndFra` for varslede endringer) og øre per poeng ved feltet «Kortbruk per år» (pris × 12 ÷ poeng per år, `tak` for opptjeningstak). Ingen velkomstbonuser eller merknader vises. `scripts/sjekk-kort.mjs` (`sjekk-kort.yml`, hver dag 05:30 UTC) henter utstedernes sider og ser at `sjekk`-tekstene i `cards.json` og Klarnas medlemskapspriser fortsatt står der – avvik blir et issue med etiketten «kortsjekk».
- DNB Mastercard Upgrade (10 p/100 kr, 59 kr/mnd, tak 500 000 kr) og DNB SAGA Mastercard Upgrade (15 p/100 kr, 169 kr/mnd, tak 700 000 kr) ligger i `cards.json` med tegnede kortbilder. Trumf Kredittkort gir ingen bonus på vanlige kjøp, bare 2 % Trumf-bonus i NorgesGruppens butikker (3 % i Trumf Pay) og 5 % hos Talkmore – derfor står det i Hverdag (`kort` i `hverdag.json`) med «+N poeng/år mot uten kortet», ikke i kortlisten. Begge sjekkes daglig av `sjekk-kort.mjs`.
- Kampanjer som ikke er butikksatser: `scripts/hent-kampanjer.mjs` (daglig) skriver `src/data/kampanjer.json` fra offisielle kilder: velkomsttilbud med faste poeng i SAS Online Shopping (samme API som butikksatsene, `commission_type: fixed` – strøm, mobil, matkasser, forsikring), partnernes egne EuroBonus-sider (Verisure, Tryg, Trygg-Hansa, Godtlevert/Linas Matkasse/Retnemt, Tre/3, Fortum, Lunar, SAS EuroBonus Mastercard SE/DK, SAS EuroBonus Business), Talkmore og Fjordkraft (Trumf-velkomstgave), Amex' kortsider (`offerHeader`), Klarnas medlemskapssider og Klarnas katalog-API (`campaignLabel`). Trumf-partnernes velkomstgaver hentes fra alle sidene under trumf.no/fordeler (fast ordlyd «Få 1500 kr i Trumf-bonus som velkomstgave», nye partnere kommer med av seg selv), Amex leses fra sideteksten («Akkurat nå: Få 30.000 EuroBonus Bonuspoeng»), og bonusen med invitasjon fra en Amex-kunde fra invitasjonssiden (NO, `/nb-no/credit-cards/apply/inviteafriend/`, «Din venn får 90.000 EuroBonus Bonuspoeng»; bare den nye kunden får poeng, og vilkårene tillater bare invitasjoner til nærstående med samtykke, så vi har ingen egen vervelenke). Svarer en kilde ikke, beholdes gårsdagens tilbud derfra. Svarer siden, men tilbudet fra i går ikke kan leses mens siden fortsatt nevner et tilbud, skrives et varsel til `kampanjesjekk.txt`, som den daglige jobben gjør om til et issue med etiketten «kampanjesjekk». Poengtallet leses fra kilden hver dag; faste vilkårstekster har `må` (tekster som må stå på siden, ellers hoppes tilbudet over). Partnere med egen side vises ikke dobbelt fra SAS-feeden. Logoer: håndplukkede offisielle logoer i `public/logos/partnere` (`src/data/partnerlogoer.json`, med kilde) går først; ellers SAS-feedens logo bare når den har gjennomsiktig bakgrunn (feeden har mange hvite flater og skjermbilder), så butikklogoen vår (ikke de fra SAS) og til slutt merkevarens ikon i Klarnas katalog med samme navn. Automatisk hentede logoer ligger i `public/logos/kampanjer` og slettes når tilbudet er borte. Nytt viser «Andre kampanjer» sortert etter poeng (Trumf-kroner omregnet), de 8 største først og resten bak «Alle N →». Oppdagelse av nye tilbud (sekundærkilder, ikke til drift): awardfares.com/blog/eurobonus-updates, eurobonusguiden.no/.se, finalcall.travel, insideflyer.no/.dk.
- Klarnas vekslingskurs til EuroBonus står på medlemskapssidene (klarna.com/no/medlemskap/plus/, /se/, /dk/): `scripts/hent-klarna-kurs.mjs` henter «12,31 SAS EuroBonus-poeng per 100 cashback-poeng» daglig og skriver den inn i `programs.json` (Danmark: 17,75). Under listen ligger «Hverdag» (`src/data/hverdag.json`): dagligvare, strøm og mobil via Trumf, med feltet «Mat per måned» og valgt kort lagt oppå.
- Følg butikk uten e-post: stjernen på en butikk lagres i nettleseren (`pointmaxing.folger`) og vises som «Dine butikker» øverst på Nytt. Utvidelsen leser samme liste og varsler når satsen går opp. Hver butikk har en Atom-strøm (`/no/kicks/feed.xml`) med satsendringer, og hvert land har `/no/feed.xml`. `/no/ukens` er ukens beste: flest poeng nå, økninger siste 7 dager og kampanjer som utløper (også i `api/ukens.json` til utvidelsen).
- `/no/flyforsinkelse` (Forsinket fly, `Flyforsinkelse.tsx`, `src/data/flyforsinkelse.json`): EU 261/2004 (250, 400 eller 600 € etter distanse) og tjenesten som fører saken, med annonselenke via Partner-ads (Flyforsinkelser.no, 35 % bare hvis de vinner – sjekkes daglig). Siden og fanen vises bare i land med en tjeneste i datafilen; i dag Norge. Personvernsiden forteller at annonselenker går via Partner-ads, som kan sette informasjonskapsler.
- `/flymedpoeng` er one-pageren til FlyMedPoeng (`FlyMedPoengSide.tsx`, `noindex`, ikke i sitemap): hva vi gir (plasseringene), hva vi ønsker (lenker tilbake, bruk i kurset, rabattkode) og hvorfor nå (Klarna Max i Norden), regnet på dagens data.
- Samarbeidspartner (`src/data/samarbeid.json`, `aktiv: false` = skjult inntil avtalen er på plass): FlyMedPoeng får én tekstlenke under resultatet i kalkulatoren (booking av reiser med poeng) og én på Kort-siden (kredittkortveiledning), bare i Norge. Teksten sier «Vår samarbeidspartner …», lenkene er `rel="sponsored"` og har UTM-parametre (`utm_source=pointmaxing`, `utm_campaign=kalkulator`/`kort`).
- SoMe-innhold: `scripts/lag-some.mjs` (del av `npm run build`) lager fire ukentlige poster til Instagram (1080×1350) og TikTok (1080×1920): ukens beste (karusell fra `dist/api/ukens.json` og `kampanjer.json`: forside, flest poeng nå, gikk opp siste 7 dager, velkomstbonuser, siste sjanse når det finnes, avslutning), butikkduellen (én populær butikk med Trumf, Klarna Max og SAS Shopping side om side) kortduellen (to kort ved 200 000 kr i kortbruk: poeng i året og pris per poeng) og Amex eller Klarna Max (Trumf + SAS Amex Elite mot Klarna Max i fire butikker der begge gir fast prosent, alltid med det sjeldne utfallet, og hvor mange butikker hver vinner). Butikker og kortpar roterer etter `src/data/some.json`, der også Amex-kortet og kortbruken settes. Tekst med emneknagger per post (`ukens.txt`, `butikkduell.txt`, `kortduell.txt`, `amexklarna.txt`). Alt ligger på `pointmaxing.no/some/` (noindex, `Disallow` i robots.txt), der bildene kan lagres fra mobilen. Frem til og med Cyber Monday lages også en Black Friday-serie med egne datoer (`dato` i `poster.json`, regnet fra `src/data/blackfriday.json`): karusell med topp 5 i hver kategori 22 dager før, «Handler du for 5 000 kr hos …?» 15 dager før, tre tips 8 dager før, flest poeng på selve dagen og på Cyber Monday (kampanjer som er beste vei når det finnes minst tre, ellers de kjente butikkene). `publiser-some.mjs` tar poster med dagens dato foran ukedagen. Skriften er Barlow fra `scripts/fonter` (OFL), gjort om til vektorer med opentype.js, så bildene ser like ut lokalt og på GitHub.
- SoMe-publisering: `scripts/publiser-some.mjs` (`publiser-some.yml`, hver dag 17:00 UTC) legger ut dagens post fra `pointmaxing.no/some/poster.json` på Instagram med Instagram API (innlogging med Instagram): JPEG-ene fra `lag-some.mjs`, karusell for ukens beste. Uten secreten `IG_TOKEN` gjør jobben ingenting. Den hopper over en post som er lagt ut siste tre døgn, og stopper hvis `poster.json` er eldre enn to dager. Tokenet (60 dager) fornyes ved hver kjøring; får det en ny verdi, lagres den med `SECRETS_PAT` hvis den finnes (fine-grained token med «Secrets: Read and write» på repoet), ellers kommer en advarsel. Manuell kjøring kan velge post. Oppsett: Instagram-kontoen må være profesjonell (bedrift eller skaper); lag en app på developers.facebook.com med bruksområdet for Instagram-innhold (Instagram API med Instagram-innlogging, tillatelsene `instagram_business_basic` og `instagram_business_content_publish`), legg til kontoen under API-oppsettet, generer token og lagre det som `IG_TOKEN` under Settings → Secrets and variables → Actions. Egen konto trenger ikke app-gjennomgang (Standard Access). TikTok: Content Posting API gjør poster fra ugodkjente apper private, så TikTok postes manuelt til en app er godkjent. Deploy kjøres hver dag fra `hent-satser.yml`, også uten nye satser, så ukens poster følger kalenderen.
- Delingsbilder (og:image, 1200×630): `scripts/lag-delingsbilder.mjs` (del av `npm run build`, etter bygg-butikksider) lager ett bilde per butikkside med poeng per 1 000 kr i hvert program (flest først, «opptil» merket), ett per land (`/og/no.png` osv.) til de andre sidene og ett per land til Black Friday-guiden, i `dist/og`. `side()` setter og:image med `?v=<hentet>`, så Facebook henter bildet på nytt når satsene endres; forsiden har sine egne tagger i `index.html`. Tegneverktøyet (Barlow som vektorer, farger, logoer) deles med SoMe-skriptet i `scripts/tegning.mjs`.
- Black Friday-guide: `/no/black-friday` (og `/se`, `/dk`), `BlackFriday.tsx`, forhåndsrendret i bygg-butikksider. Kjente nettbutikker per kategori i `src/data/blackfriday.json` (dato, Cyber Monday og butikk-id-er per land og kategori), sortert etter poeng med brukerens eget oppsett, «Kampanjer nå» der en kampanje er beste vei i butikken, og tre tips regnet fra programmene (Klarna Max-faktoren, hvilke programmer kortet gir poeng i). Menyvalget vises til og med Cyber Monday. Bytt datoer og sjekk butikklistene hvert år.
- `/klarna` er partnersiden til Klarna (norske tall, `noindex`, ikke i sitemap): Max-effekten i hver butikk, kortsiden og utvidelsen i Google-søk.
- Nettleserutvidelse (Chrome, Manifest V3) ligger i `extension/`. Den henter `https://pointmaxing.no/api/butikker.json` daglig og viser beste poeng per 100 kr som merke på ikonet når du er inne på en kjent butikk, og legger en stripe øverst på Google-søk med Trumf, Klarna og SAS side om side for butikkene i treffene (lys og mørk drakt følger Google). Klarna-nivået og butikkene du følger på pointmaxing.no synkroniseres til utvidelsen (`synk.js` leser nettsidens localStorage); nivået kan også byttes i popupen. På nettbutikker vi har satser for viser `butikk.js` et lite kort nede til høyre med programmene og «Åpne via …» til siden kjøpet må starte fra – domenene skrives inn i manifestet av `npm run utvidelse` (kjøres også av den daglige jobben). Den daglige hentingen i utvidelsen sammenligner satsene for fulgte butikker og gir Chrome-varsel når en går opp. `manifest.firefox.json` er samme utvidelse for Firefox (bakgrunnsscript i stedet for service worker) – ikke testet. Last inn via chrome://extensions → Utviklermodus → «Last inn upakket».
